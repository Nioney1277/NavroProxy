# 载具预测

Navro 使用独立实现对齐 CultAC Bedrock 载具的物理公式与控制分支，代码复用 Navro 自有的世界、碰撞与传输接口，不引入 Cult 源码或依赖，项目继续使用 MIT 许可。当前对齐参考 Cult commit `8327a7031259e7757a2b4cebc3eff71d64756eb5`；物理对齐不包含 Cult 的检测阈值或回拉策略，也不改变 Navro 的误差配置。

支持协议 944（1.26.10）及之后的客户端预测载具输入。连接代理的协议范围不受这个检测门槛影响。

| 载具 | 接入内容 |
| --- | --- |
| 船、运输船 | 模拟/数字划桨、划桨衰减、转向惯性、低速转向增强、水/地面/空中阻力、重力与浮力、长时间淹没失控、碰撞 |
| 马、驴、骡、骷髅马、僵尸马 | 马鞍及驾驶席确认、服务端速度/跳跃属性、缓动转向、蓄力跳跃和前冲、抬腿时的移动限制、步高、地面/空中/液体运动、跳跃提升/漂浮/缓降效果、碰撞 |

触屏仅在 `TOUCH + CLASSIC` 布局下使用独立双桨按钮，其余布局使用 AuthInput 的 `motion` 控制向量。向量按长度归一化，船的 `UP` 标志随后覆盖前进轴；步行用的 `analogMoveVector` 不作为载具控制源。

浮力组件的 `apply_gravity` 决定船的重力。转发组件时统一设置 `movement_type: none`、`simulate_waves: false`，使客户端与预测采用相同的无随机波浪模式。组件更新仍按关闭 ACK 提交到预测状态。浸没的气泡柱在移动后调整竖直速度，位于柱顶上方的接触不作为浸没推动。

预测从服务端实体位置、速度、旋转及已确认元数据建立基准。普通移动回显不会覆盖正在运行的本地载具预测；强制移动、速度包、属性、药水效果及载具纠正按各自的关闭 ACK 生效。实体连接使用 unique ID，预测载具输入使用 runtime ID；驾驶员与乘客分别处理。马类优先使用已确认的骑乘座位高度，没有座位数据时使用对应原版马类的默认高度。船的预测 pose 会在移动后写回实体缓存，包含位置、速度、朝向、角速度和着地状态，供实体碰撞、下船和重新上船使用；普通远端移动回显不覆盖本地控制结果，服务端强制移动仍重置该 pose。

已确认驾驶员缺少载具预测标志、提交错误实体 ID 或非有限控制值时，不能退出校验。预测结果决定转发的位置、速度与载具旋转；超差遵循 `smooth-setback`：`false` 默认强制同步载具，`true` 保留 `PredictionType.VEHICLE` 软纠正，不触发普通玩家步行检查。船的默认物理包围盒为 1.375 × 0.5625，已确认的服务端宽度、高度和缩放会覆盖默认值。

RakNet Java 检测入口与 NetherNet 检测入口共享 `SessionState` 中的同一预测器。只有连接/透传的链路不会因此启用反作弊。

服务端载具纠正按 simulation frame 查找载具历史，保留划桨、转向和马跳跃/抬腿状态并重放后续输入。速度、属性、强制位置等外部变更会使旧历史失效；缺少来源历史或地形时不猜测旧状态。重放使用当前已经确认的世界碰撞数据，尚未实现载具专用的历史方块快照。预测的实体 pose 写回补偿实体缓存，普通本地移动回显不会在延迟 ACK 后覆盖它；再次上船使用最后可信 pose。

乘客、低于 944 的协议、未装备马鞍或缺少速度/跳跃属性的马，以及不能解析的自定义浮力组件保留原有骑乘转发。骆驼、羊驼、猪、炽足兽、矿车等不属于本次模型。未加载地形会暂停推进载具基准，不按不存在的空气地形接受移动。

测试覆盖公式数值、马类状态、实体 pose 发布、完整 AuthInput 流程、控制权和 ACK 边界、上下坐骑、实体删除、碰撞、浮力、跳跃、延迟纠正重放、换维度，以及 NetherNet 原生编解码与纠正传输。扩大回归另排除了一个在部署前 JAR 上同样失败的旧 `PostAuthInputReferenceTest`。尚未用同一世界快照对 Cult 和 Navro 做逐帧差分，也未完成本轮改动部署后的真实客户端进服复测。

本模块对齐物理计算与控制条件；误差判定使用 Navro 的 `player-position-acceptance-threshold`，没有额外的位置容差下限或转向差阈值。

| 参考控制/物理分支 | Cult 参考文件 |
| --- | --- |
| 输入布局、步高属性 | `BedrockMovementInputFactory` |
| 有限轴输入、双桨按钮、向量归一化、UP | `BedrockControlInput` |
| 划桨计时及按下/松开衰减 | `BedrockBoatState.Paddle` |
| 船的表面阻力、低速转向、淹没失控、移动后浮力 | `BedrockBoatMovement` |
| 重力组件、船体元数据、无随机波浪模式 | `GeyserBoatMetadata` |
| 浸没气泡柱推动 | `BedrockBoatInsideMovement` |
| 马类缓动转向、蓄力及跳跃资格 | `BedrockHorseMovement` / `BedrockHorseState` |

`/navro debug <player>` 与 `/navro debug2 [player]` 也订阅载具预测。输出包括载具类型、运行状态、预测/实际位移、预测/实际末速度和转向。乘客、未支持载具及地形等待会明确显示状态与 `N/A`，不会把未执行的预测标成零误差。

## 上下船与零竖直运动

上下船参照 Cult commit `8327a7031259e7757a2b4cebc3eff71d64756eb5` 的 Bedrock 分支，接入 Navro 自己的实体与 ACK 接口。服务端已发送的关系与客户端已确认的关系分开记录，每次骑乘有独立对象，确保尚未确认上船就收到下船、同批重新上船和迟到 REMOVE 不作用于另一轮骑乘。

可控制载具的新一轮上船从该实体的可信位置、朝向初始化，并与客户端显式同步零速度与零转向惯性；玩家跑步速度不带入载具。相同骑乘关系的重复包不会重复初始化。常规载具移动回显仍不覆盖本地预测，强制移动按自己的 ACK 生效。

主动下船请求只记录意图，不再使用旧 Boar 的“后方一格”候选落点。等待当前骑乘的服务端 REMOVE 或已确认的下船传送。下船时重建玩家碰撞盒、清理骑乘历史和旧速度候选；优先使用当前骑乘的服务端下船位置。没有这个位置时，代理在 REMOVE 确认后从最后可信位置发送零速度和明确的步行传送，以实际发出的包作为新基准。等待这个传送的 ACK 和客户端确认期间不把步行坐标当作载具坐标。无发送通道时保持等待服务端位置，不接纳客户端自报落点。

Navro 的同步时机适配直接 Bedrock 链路，未引入 Java 客户端的保留骑乘速度分支。服务端下船位置优先；零竖直运动在没有竖直碰撞且请求竖直位移绝对值不超过 `1e-9` 时保留上一帧着地状态，其余由碰撞计算更新。

## 方块边缘

船的碰撞仍使用完整船体。表面取值参照 Cult `BedrockBoatMovement.surface`：船中心所在格为空气或雪层且船仍着地时取下方方块；下方为空气或采样结果缺省时使用空气摩擦 `0.9`。船体完全离地后使用普通空中系数 `1.0`（拴绳分支 `0.91`），并停止划桨推力。浮力仍按中心对应液体和液面判断。回归覆盖中心越过方块边界、船底仍有支撑的情况；不以扩大误差阈值掩盖切换差异。

## VehiclePrediction 检测

`VehiclePrediction` 是独立注册的检测与 VL 项。仅对可控制载具、有效输入、已知地形并完成预测的位移超差记 VL；正常移动、等待地形、上下船等待和玩家豁免不记 VL。位置阈值沿用 `player-position-acceptance-threshold`，警报门槛沿用 `differ-till-alert`。

警报布局沿用 Prediction 检测：`<玩家> failed VehiclePrediction x<VL> o: <误差>, expected: <预测位移>, actual: <实际位移>`。`disabled-checks: [VehiclePrediction]` 关闭此项报错，现有载具物理和纠正机制仍继续。`punishments.yml` 中新增独立 `VehiclePrediction` 组，默认每次警报，不默认踢出玩家。该改动不混入 Horizonal/Vertical 的 VL。

以上是源码与回归对齐，尚未完成相同地形、相同输入下的 Cult/Navro 逐帧实机对比，不宣称所有浮点边界和自定义组件逐位相同。

## 原版方块物理属性

协议 2225（1.26.60）通过 `BedrockBlockProperties` 加载独立的 BDS 1.26.63.1 数据，23,960 个完整状态与当前调色板逐项匹配。Registry 在建立数值/哈希索引或读取重排调色板时按名称及带 NBT 类型的状态绑定属性；预测阶段直接读取状态对象缓存，不扫描表，也不改写网络 NBT。

`NavroBlockState.getFriction()` 对已覆盖的原版状态使用导出摩擦。服务端方块组件优先，未覆盖协议和状态保留已有 fallback。船表面算法中“空气应取下方支撑块”等分支保留，不能把空气的材质摩擦直接当成船地面摩擦。载具跳跃判定读取 `PREVENT_JUMPING` 与 `CHECK_BELOW`，因此站在蜂蜜上的地毯时会按原版属性继续检查蜂蜜。

材质 `blocksMotion`、`solid`、`liquid` 通过同一属性对象提供查询。这里的 `solid` 是材质实心标志，不是实体碰撞形状或某个面的支撑能力，因此没有直接替换 `FluidBlockCollision` 的碰撞和面判定。细节、来源和数据更新方法见 [bedrock-block-properties.md](bedrock-block-properties.md)。


## 载具拉回模式

载具与步行共用 `smooth-setback`。`false` 的硬模式参考 Grim 的结束骑乘流程：先发送 REMOVE 骑乘关系、可信载具位置和零载具速度，并向后端发送标准 LEAVE_VEHICLE 请求。收到同一骑乘实例的后端 REMOVE 确认后才清除本地骑乘，重建人物碰撞盒并发送步行 MovePlayer TELEPORT 和零人物速度。目标坐标与 HANDLE_TELEPORT 都必须匹配，网络 ACK 本身不能授权客户端位置。

硬拉回不会自动重新上船。未完成确认时阻止旧载具输入和重新骑乘；确认后再限制十个输入处理步的实体交互。确认前的旧骑乘包不能恢复当前骑乘；服务器明确切换到另一载具时，旧拉回作废，等换乘确认后再恢复预测。纠正确认后的真实服务器挂载仍遵循服务器状态。后端未解除骑乘会按 max-latency-wait 超时断开，不能长期允许客户端、代理与后端保持不同骑乘状态。

`true` 保留原来的 VEHICLE 类型 CorrectPlayerMovePredictionPacket 纠正，保持骑乘。初始化上船时的零速度、位置同步由独立 synchronizeVehicleMount 路径处理，不触发强制下船。

已撤掉上方一格再返回的双定位方案。该方案的参考模型没有覆盖客户端预测载具的另一条接收路径，实服残差说明它不能作为可靠硬拉回。
