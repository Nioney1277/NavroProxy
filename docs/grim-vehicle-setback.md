# Grim 风格载具硬拉回

依据 Grim 2.0 分支提交 `8064a40b8e1fb2d3760f77ea62d3f88f377ef804` 的 SetbackTeleportUtil.sendSetback：通知客户端下船、同步后端解除骑乘、移动载具、传送玩家，确认后保留短暂交互冷却，不自动恢复骑乘。Java 的 Bukkit eject 与传送 ID 不能直接套入 Bedrock 包。

Navro 先发送客户端 REMOVE、载具可信位置和零速度，再通过普通服务端通道发送 LEAVE_VEHICLE（目标为载具 runtime ID）。NetherNet 将请求放在当前已校验输入之后；RakNet 延迟到当前处理结束发送，避免后端先收到退出再收到旧骑乘输入。该标准协议通道不要求更新桥接插件。

收到该骑乘实例的后端移除包并经客户端 ACK 确认后，再清除本地载具状态，执行带严格坐标和 HANDLE_TELEPORT 校验的步行硬传送。目标是结束客户端对载具的持续预测控制，不再反复设置已失效的同一旧轨迹。后端移除失败或拒绝时不会假装同步成功，而是等待配置的超时后断开。

软模式保留。初始化上船同步独立，不触发强制下船。延迟确认、换乘、旧关系重放、传输失败与超时都有定向验证；真实客户端效果仍需复测。
